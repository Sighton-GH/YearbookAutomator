# Spec sheet — Plan 2: maximum customisation of yearbook spreads

Read `00-README-handoff.md` first. Implement after (or merged on top of) `01-plan3-remaining-bugs.md`; §7 of the README lists where the two meet. Item IDs (`F1.1` …) go in commit subjects and `DELIVERY.md`.

**Goal:** a yearbook editor can make the finished spread look the way their designer intended — text, per-student exceptions, slot layout, photo framing and print output — without leaving the tool, and what they see in the tool is what prints.

## Ground rules for every feature

1. **Defaults reproduce today's output exactly.** An old saved session/config (no new fields) must render pixel-identically to base `170fd1a`. Add one backend "golden" regression test that renders a synthetic project with all defaults and compares against an image produced at the base commit (store the expected PNG under `tool/server/tests/golden/` generated by a script you also commit, from synthetic data only — no binary student data).
2. **Contract first.** All new request fields below go into `tool/server/app/models/schemas.py` with Pydantic validation (ranges, hex colours via the existing validator style used for `baby_background_color`), mirrored in `tool/web/src/types.ts` / `api.ts`, sent by `runGeneration` in `App.tsx`, persisted in `PersistedSessionV1` (`session.ts`), and round-tripped by config export/import. Use the exact field names given here.
3. **Preview = output.** The Style step's live preview is currently a CSS approximation (`steps/edit/StyleTab.tsx`). Add **F1.8 "Render test strip"** first, then use it to verify every text/photo feature visually.
4. **Fallbacks are announced.** Anything that cannot be honoured (missing glyph, font without italic, no face found, unsupported script) appends a plain-English entry to the generation job `warnings` list (added by P3-03).
5. **Every feature:** backend unit test(s) for the rendering/logic, and a Playwright e2e that sets the control in the UI, renders, and checks the effect (via the verification spreadsheet, the saved generation request JSON, or simple pixel sampling of the output).

## F1 — Text styling (Style step)

Controls live in the Style step (`steps/edit/StyleTab.tsx`, `components/FontPick.tsx`). Today: font family, size (1–500), weight normal/bold, align left/centre, all caps — separately for names and quotes. Text colour is hard-coded `(20, 30, 50)` in `generator.py` (`_render_name`, `_render_wrapped_text`) and `tiff_layers.py`.

New `GenerationRequest` fields (for each of `name_` and `quote_` prefixes; all optional, default = today):

| Field | Type / range | Default (today) |
|---|---|---|
| `{p}_color` | hex string | `#141e32` |
| `{p}_align` | add `"right"`; quotes also `"justify"` | unchanged |
| `{p}_valign` | `"top" \| "middle" \| "bottom"` (within the text box) | `"top"` |
| `{p}_line_spacing` | float 0.5–3.0 (multiple of font size) | `null` = today's spacing (`0` px extra for quotes; single-line names) |
| `{p}_letter_spacing` | int −5–50 px at output resolution | `0` |
| `{p}_stroke_width` / `{p}_stroke_color` | int 0–20 / hex | `0` / `#ffffff` |
| `{p}_shadow` | `{offset_x:int, offset_y:int, blur:int 0–20, color:hex, opacity:0–1}` or null | `null` |
| `{p}_font_style` | `"normal" \| "italic"` | `"normal"` |
| `name_fit` | `"shrink" \| "wrap"` | `"shrink"` (current: one line, shrink to fit width) |
| `name_min_size` / `quote_min_size` | int 6–200 | `8` |

- **F1.1 Alignment:** right for names and quotes, justify for quotes (last line left-aligned), vertical alignment inside the guide box. For quotes keep the existing geometry rule (max width `min(quote.width, mugshot.width*1.5)`, max height `mugshot.height`) — vertical alignment applies within that area.
- **F1.2 Colour:** colour pickers (swatch + hex input) for names and quotes.
- **F1.3 Spacing:** line spacing and letter spacing (letter spacing needs per-character drawing; keep kerning by measuring with `font.getlength` per glyph pair).
- **F1.4 Outline and shadow:** Pillow `stroke_width`/`stroke_fill`; shadow drawn on a separate RGBA layer, blurred with `ImageFilter.GaussianBlur`, composited under the text.
- **F1.5 Name fitting:** `"wrap"` allows up to 2 lines before shrinking; both modes respect `name_min_size`; if text still doesn't fit at min size, draw at min size and add a warning naming the student (today it silently overflows).
- **F1.6 Italic and real weights:** resolve italic faces in `services/fonts.py` (`resolve_font_file` already scores by OS/2 metrics — add italic as a target instead of a penalty when requested). For **variable fonts** (file has an `fvar` table) set the weight axis via `font.set_variation_by_axes` (`wght` = 400/700) and italic/slant axes when present. If the family has no italic, warn (P3-03 warnings) and render upright.
- **F1.7 Glyph fallback and scripts:** per-character fallback to an installed font that has the glyph (search the system font index for coverage via `fontTools` cmap; cache per codepoint), so emoji and CJK don't print as boxes; colour emoji via a CBDT/COLR font if installed (`Noto Color Emoji`) rendered with `embedded_color=True`, else monochrome fallback + warning. Right-to-left text: if Pillow has libraqm (`features.check("raqm")`), pass `direction`/`language`; if not, warn that RTL may render incorrectly. Never crash on any Unicode input.
- **F1.8 Render test strip:** Style step button "Preview with real rendering" calls the backend to render the first 2 slots (names + quotes) at reduced size (new lightweight endpoint or `generate` with `output_filename="preview_strip.png"` and 2 people) and shows the image beside the CSS preview. Update the caption to say the strip is exact.

## F2 — Per-student editing (People step)

People grid: `steps/edit/PeopleTab.tsx`, Inspector: `components/PersonInspector.tsx`, records: `PersonRecord` in `schemas.py` / `api.ts`. Use the People state lifted by P3-02.

- **F2.1 Edit names:** first/last name fields in the Inspector (fixing typos without re-ingesting). Edits survive re-ingest only if the user chooses "keep my edits" when re-ingesting (show a diff summary: N names edited will be overwritten / kept).
- **F2.2 Add and remove students:** "Add student" (first, last, optional portrait upload, quote) appends a person with a new unique `index` (max+1) marked `added_manually: true`; "Remove from yearbook" sets `excluded: true` (kept in the list greyed out, skipped by generation, restorable). Both fields optional on `PersonRecord`, default false; the generator and spread chunking skip excluded people.
- **F2.3 Per-student overrides** (optional `PersonRecord` fields, null = use global): `name_font_size`, `quote_font_size`, `name_color`, `quote_color`, `hide_baby_photo` (bool), and the `quote_blank` flag from P3-17. Inspector section "Overrides for this student" with reset-to-global per field. Generator applies them per person.
- **F2.4 Pick any uploaded portrait:** Inspector "Choose from uploaded photos" opens a searchable grid of files in the workspace `mugshots/` (new `GET /api/mapping/assets?kind=mugshot` listing names + thumbnails via the existing `/api/mapping/asset` route); choosing sets `mugshot_filename`. Same for baby photos.
- **F2.5 Place a student in a specific slot:** Inspector "Position" control (spread number + slot number, with a mini slot map of the template showing numbers) writing `slot_assignments` (`App.tsx` state already exists and is sent; no UI writes it today). Show conflicts the way `services/placement.py` resolves them (explicit assignments claim first) — preview who moves.
- **F2.6 Match portraits by a filename column:** many photo vendors export the roster with a column naming each student's image file (e.g. `SelectedImage`, `Image`, `Photo`, `Filename`). On the Roster & Photos step, if such a column exists, offer "Match portraits using the '<column>' column" (default on when ≥ 80 % of its values exist in the ZIP). Backend: `ingest_spreadsheet(..., filename_column: str | None)` in `services/spreadsheet.py` maps by exact filename (case-insensitive, extension-insensitive fallback), before name/number matching. Warn for listed files missing from the ZIP.
- **F2.7 Bulk actions:** toolbar with "Select all / none", then for the selection: clear quotes, clear baby photos, exclude, include, apply override (font size), re-run face centring / background removal (queued one at a time through the existing job endpoints with a progress bar).

## F3 — Layout editing (Template step)

Layout editor: `steps/edit/LayoutTab.tsx`, canvas `components/TemplatePreview.tsx`, fields `components/SlotInspectorFields.tsx`, helpers `utils/slots.ts` (`clampBox` exists at base). Slots are `TemplateSlots` = `{mugshot, baby_photo, name, quote}` boxes.

- **F3.1 Add / delete / duplicate slots:** "Add slot" drops a default 4-box slot (sized like the median existing slot) at the canvas centre; "Duplicate" copies the selected slot offset by 20 px; "Delete" removes it (confirm). Slots without a baby box or quote box are allowed if those features are off.
- **F3.2 Slot numbers and order:** draw the slot number (in fill order for the current placement mode) on the canvas; "Renumber" mode where clicking slots in sequence sets the order (stored as slot array order; placement mode remap still applies on top — show the effective numbers).
- **F3.3 Usable handles at any resolution:** handle radius and stroke scale with the displayed size (constant ~8 CSS px); only the selected box shows handles; zoom (wheel/pinch, buttons) and pan (space-drag); keyboard nudge (arrows 1 px, shift+arrows 10 px) for the selected box.
- **F3.4 Undo / redo:** history for all layout edits including regroup, re-parse, reset slot, add/delete; Ctrl/Cmd-Z, Shift-Ctrl/Cmd-Z, toolbar buttons; at least 50 steps; not persisted across reloads.
- **F3.5 Detection tuning:** on the Template card, a "Detection sensitivity" slider (maps to the parser's HSV tolerance sweep; add an optional `tolerance` form field to `POST /api/templates/parse` → `template_parser.py`) and a "Show what was detected" toggle that overlays the raw detected boxes per colour (`raw_debug` from the parse response) with counts and a line like "3 extra name boxes were ignored" / "2 quote boxes were guessed — please check them" (have the parser report dropped and invented boxes in `raw_debug`).
- **F3.6 Baby cutout masks follow edits:** when a baby box is moved/resized, regenerate its mask from the stored annotated template (`uploads/template_annotated.png`) for the new box (new endpoint `POST /api/templates/baby-mask` taking the box) instead of relying on the IoU ≥ 0.8 fallback in `generator._find_baby_mask_path`; add a per-slot "Cutout shape" override (`auto | rectangle | ellipse | rounded`) stored on the slot (`TemplateSlots.baby_shape`, optional).

## F4 — Photo framing and print (People + Generate steps)

Portraits are pasted with scale-to-cover and a dead-centre crop (`generator.py` `_paste_image`, `_fit_image`); baby photos have optional face centring and a mask.

New `GenerationRequest` fields (defaults = today):

| Field | Type | Default |
|---|---|---|
| `mugshot_fit` | `"cover" \| "contain"` | `"cover"` |
| `mugshot_face_aware` | bool — centre the cover crop on the detected face (shared detector from P3-06) | `false` |
| `mugshot_shape` | `"rect" \| "rounded" \| "ellipse"` | `"rect"` |
| `mugshot_corner_radius` | int px 0–500 | `0` |
| `mugshot_border_width` / `mugshot_border_color` | int 0–100 / hex | `0` / `#ffffff` |
| `mugshot_shadow` | same shape as text shadow | `null` |
| `contain_fill_color` | hex, used when `mugshot_fit="contain"` | `#ffffff` |
| `output_dpi` | int 72–1200 | `300` (P3-12 constant) |
| `crop_marks` | bool (PDF only) | `false` |

Per-student (`PersonRecord`, optional): `mugshot_focus: {x: float 0–1, y: float 0–1, zoom: float 1–4}`, `baby_fill_color: hex | null`.

- **F4.1 Portrait framing:** global fit/face-aware options on Generate (or Style) plus a per-student "Adjust portrait" editor (reuse the cropping approach of `BabyPhotoEditor.tsx`; do **not** fork it — extract the shared cropper into a component used by both) that sets `mugshot_focus`. Render honours focus > face-aware > centre.
- **F4.2 Portrait shape, border and shadow:** rounded corners/ellipse via an alpha mask, border drawn inside the box edge, shadow as for text. Same options for baby photos where the template mask is "auto rectangle".
- **F4.3 Print settings:** Generate gets "Print" settings: DPI (72/150/300/600 or custom), shows physical size per spread, warns when portraits will be upscaled more than 1.5× at that DPI ("4 portraits are lower resolution than this print size needs"), optional PDF crop marks (draw marks outside the page by extending the PDF canvas by 0.25 in and setting `TrimBox`), and a "Show safe area" overlay on the Template step (configurable inset in mm, default 3 mm bleed / 6 mm safe — overlay only, does not change output).
- **F4.4 Layered TIFF:** `services/tiff_layers.py` `save_layered_tiff` exists but nothing calls it. Add output format `"tiff_layered"` ("TIFF with layers (Photoshop)") that writes background, photos and text as separate layers, behind an admin toggle like the other formats (`enable_tiff_output`). If you cannot make Photoshop-readable layers reliable, delete the dead code instead and say so in `DELIVERY.md`.
- **F4.5 Baby photo fill per student:** `baby_fill_color` override (keep transparency vs fill), editable in the Inspector next to the existing global "baby background colour".
