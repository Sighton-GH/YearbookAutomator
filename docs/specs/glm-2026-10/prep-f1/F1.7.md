# F1.7 prep: Unicode capability and fallback

Partial helpers only, deliberately NOT wired into text_layout. `font_coverage(path)` caches cmap; `fallback_path(codepoint, paths_tuple, prefer_color=False)` caches per codepoint and candidate set; `glyph_runs(text, primary, size, paths=None, warnings=None)` chooses loadable covering fonts, coalesces same-font runs and returns GlyphRun(text, font, embedded_color). `script_kwargs(text, language=None, warnings=None)` returns RTL direction/language with raqm or warns without it. `draw_unicode(draw, xy, text, font, size, ..., warnings=None)` is an isolated left/top run drawer for experimentation.

Integrator must use glyph runs consistently in measurement/wrapping/painting (not just swap draw calls), and call clear_glyph_caches after font changes. For legacy sessions retain base shaping and font selection. Complex-script multi-font run ordering and combining/ZWJ clusters are NOT solved; warnings announce splitting and mixed-font RTL ordering risk. No claim of universal Unicode correctness. Missing glyphs become ? with a warning. Bitmap-only colour emoji that cannot load at target size are skipped for another face; monochrome/missing emoji warns. Embedded colour support is requested for usable CBDT/COLR faces.

Tests cover Latin run retention, cmap fallback cache, raqm branches, unsupported codepoints, surrogate/emoji no-crash. Real installed CJK/colour emoji, mixed-font RTL pixels, complex scripts, UI/e2e remain unverified. No installed emoji/CJK fonts are assumed and none downloaded.
